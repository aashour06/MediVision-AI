# MediVision AI

### Predictive Health Analytics & Gemini-Powered Conversational Assistant

MediVision AI is a machine-learning health analytics project that
estimates selected health-risk probabilities from structured patient
data. This branch extends the existing application with a conversational
assistant powered by the Google Gemini API, so users can ask general
questions about the platform and---when they explicitly
consent---request a plain-language explanation of results generated by
the application's ML models.

> **Important:** MediVision AI is an educational and informational
> project. Its predictions are not medical diagnoses and must not be
> used as a substitute for professional medical advice.

## Project Overview

MediVision AI combines two components:

1.  **Predictive ML service** --- uses the project's trained
    scikit-learn models to estimate risk for supported health targets
    from structured patient features.
2.  **Conversational assistant** --- uses Gemini to answer general
    questions and explain application-generated results in accessible
    language.

The chatbot does not replace the ML pipeline. When patient-specific
analysis is requested, the backend calculates the results with the
existing models and provides those results as context to Gemini. The
assistant is instructed not to invent or alter predictions.

## Key Features

-   Predictive health-risk analytics using trained machine-learning
    models.
-   Web dashboard for entering patient features and viewing predictions.
-   Floating chatbot integrated into the existing frontend.
-   Arabic and English response options, with automatic language mode.
-   In-session conversation history sent with chat requests.
-   Optional patient-profile context for explaining current ML results.
-   Explicit consent gate before patient-profile data is processed
    through the chatbot flow.
-   Server-side Gemini API integration; the API key is not intended to
    be placed in frontend code.
-   Request validation and user-facing error handling.
-   Existing data, trained models, notebooks, and reports retained as
    part of the project.

## How It Works

``` text
User
 │
 ▼
Web Dashboard (Vue 3)
 │
 ├── Health prediction request ──► FastAPI /predict ──► Trained ML models
 │                                                        │
 │                                                        ▼
 │                                                  Prediction results
 │
 └── Chat message ───────────────► FastAPI /chat ─────► Gemini API
                                      │                    ▲
                                      └─ Optional ML results┘
                                         (with consent)
```

The application backend is responsible for running predictions and
managing the Gemini request. Gemini is used to generate conversational
explanations; it is not the source of the model's numeric prediction
results.

## Getting Started

### Prerequisites

-   Windows, macOS, or Linux with a compatible Python installation.
-   Python **3.13 or later**, matching the backend project's declared
    Python requirement.
-   A Google Gemini API key for chatbot functionality.
-   Internet access for Gemini requests and any CDN-loaded frontend
    assets.

### 1. Clone the repository

``` bash
git clone https://github.com/aashour06/MediVision-AI.git
cd MediVision-AI
```

To use the chatbot integration from this branch:

``` bash
git switch feature/medivision-ai-chatbot
```

### 2. Install backend dependencies

From the repository root, run:

``` bash
python -m pip install -r backend/requirements.txt
```

Alternatively, if you use `uv`, sync the backend project from its
directory:

``` bash
cd backend
uv sync
```

Use one dependency-management workflow consistently. The `uv.lock` file
is maintained for the `uv` workflow.

## Configuration

Set the Gemini settings in the environment where the backend process
will run. Do not commit a real API key.

**PowerShell (current terminal session):**

``` powershell
$env:GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
$env:GEMINI_MODEL="YOUR_AVAILABLE_GEMINI_MODEL"
```

`GEMINI_API_KEY` is required for the chatbot endpoint. `GEMINI_MODEL` is
optional if the backend has a default model configured; if set, it must
name a model available to your Google Gen AI API account.

These environment variables are session-scoped in PowerShell. Set them
again in a new terminal session, or configure them securely using your
preferred environment-management method.

## Running the Application

### 1. Start the backend

From the repository root:

``` bash
python -m uvicorn backend.main:app --reload
```

If your local setup uses the provided Windows helper, you can also
inspect and run `start_backend.bat` after confirming its environment and
working-directory assumptions.

The API should be available at:

-   Base URL: `http://localhost:8000`
-   Interactive API documentation: `http://localhost:8000/docs`

### 2. Open the frontend

Open `frontend/index.html` in a browser. The current frontend is
configured to send API requests to `http://localhost:8000`.

If the browser blocks requests because of local-file or CORS
restrictions, serve the frontend through a local static HTTP server and
ensure the backend's CORS configuration permits that origin.

### 3. Try the chatbot

Open the chat widget in the dashboard and ask a general question about
the platform. To ask for an explanation of patient-specific results, use
the consent control in the interface. Only share health information when
you understand and agree to the data flow.

## API Overview

### `POST /predict`

Accepts structured patient features and returns prediction information
from the trained models. Consult `/docs` for the exact request schema
and response format implemented in the checked-out version.

### `POST /chat`

Accepts a chat message and can include language preference, recent
conversation history, and an optional patient profile.

Conceptual request fields:

  -----------------------------------------------------------------------
  Field                               Purpose
  ----------------------------------- -----------------------------------
  `message`                           User's message

  `language`                          `auto`, `ar`, or `en`

  `history`                           Recent user/assistant messages

  `profile`                           Optional patient feature payload

  `consent_to_send_health_data`       Must be true to process a supplied
                                      patient profile in the chat flow
  -----------------------------------------------------------------------

When a patient profile is supplied without consent, the endpoint rejects
the request. When a profile is included with consent, the backend
calculates the ML analysis and uses the resulting data as context for
the Gemini response. A general chat request can omit the profile.

The exact schemas and error responses are defined by the backend code
and can be inspected at `http://localhost:8000/docs` while the service
is running.

## Privacy and Security

-   **Never commit API keys.** Keep `GEMINI_API_KEY` in an environment
    variable or a secure secret manager.
-   Do not place the Gemini API key in `frontend/index.html` or any
    browser-side JavaScript.
-   Do not commit `.env` files containing secrets. The repository's
    `.gitignore` should continue to exclude them.
-   Patient-specific information should only be sent through the chatbot
    flow after the user has explicitly consented.
-   Avoid using real identifying patient information during development
    or demonstrations.
-   Review logs, API payloads, and deployment settings before exposing
    the service publicly.
-   The consent interface is an application-level safeguard; it is not a
    substitute for a formal privacy, security, or regulatory review.

## Limitations

-   Predictions depend on the quality, coverage, and limitations of the
    training data and models.
-   Model probabilities should not automatically be interpreted as
    clinically calibrated individual risk.
-   Model performance can vary by population and data quality; review
    the project's evaluation materials before drawing conclusions.
-   The chatbot can generate incorrect or incomplete text. Verify
    important information independently.
-   The application is not a diagnostic system and does not prescribe
    medications or treatments.
-   The current frontend uses a local backend URL; production deployment
    requires configuring the API URL, CORS, authentication, transport
    security, and secret management appropriately.

## Development Notes

-   Keep the ML prediction logic in the backend; do not rely on Gemini
    to calculate or invent prediction scores.
-   When changing the input features, update the request schema and
    confirm that feature order matches the saved model artifacts.
-   Keep `backend/requirements.txt`, `backend/pyproject.toml`, and
    `backend/uv.lock` consistent when dependencies change.
-   Test both `/predict` and `/chat` after modifying backend behavior.
-   Test general chat separately from consent-based patient-profile
    explanations.
-   Do not commit Python cache files, virtual environments, local
    secrets, or machine-specific configuration.
